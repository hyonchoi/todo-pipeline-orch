## Affected Pages/Routes
- No web pages or routes. Verify the `tpo config` CLI and Hermes kanban task bodies.

## Key Interactions to Verify
- `tpo config init/get/set agent_client` accepts `claude` and `codex`, reports the source, and persists the selected value.
- Production `tpo tick` passes both the global agent client and the contract-selected phase profile into task registration.
- The harness passes the selected agent client through full-profile and filtered `--phase` registration.
- Every bundled gstack and agent-skills phase renders the selected product label and skill prefix without changing unrelated slashes, paths, or URLs.
- Registration validates and renders all phase bodies before creating the first Hermes task.

## Edge Cases
- Missing `agent_client` defaults to `claude`.
- YAML null, case mismatch, and unknown client values fail with actionable source-aware errors.
- Unknown, positional, malformed, and unresolved template fields raise `PhasePromptRenderError`.
- Escaped literal braces render normally.
- A render failure creates zero tasks and records `failed_to_spawn`.
- Ordinary, possessive, and namespaced skill references render correctly for both clients.
- Every bundled skill reference appears in the prerequisite matrix.

## Critical Paths
- Global config -> production tick -> contract profile resolution -> two-pass registration -> client-correct Hermes task body.
- Global config -> harness -> filtered/full phase registration -> client-correct task body.
- Invalid bundled template -> zero task mutations -> visible failure outcome and actionable error.
- Release qualification: smoke one externally verified phase for each supported client/profile pair without making external distributions normal-CI dependencies.
