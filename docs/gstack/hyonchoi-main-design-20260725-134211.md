## Problem Statement

All pipeline configuration lives in hardcoded defaults (`Config` dataclass) or environment variables (`PIPELINE_*`). Users who want to change `projects_dir` or any other setting must export an env var — no persistent config file exists. There is no `tpo config` CLI to inspect or modify settings.

## What Makes This Cool

A single `~/.config/tpo/config.yaml` file replaces scattered env vars. `tpo config init` generates a self-documenting skeleton with all fields and defaults. `tpo config set projects_dir /opt/projects` and it just works — schema-validated, type-coerced, no guessing.

## Constraints

- PyYAML is already a dependency (`pyyaml>=6.0` in pyproject.toml)
- `Config` dataclass is frozen — use `dataclasses.replace()` for overrides
- Existing env var overrides (`PIPELINE_*`) must continue to work AND layer on top of config file
- The `skills` subcommand bypasses `Config.from_env()` to work without config — `tpo config` must do the same
- Per-project TOML overlay (`load_toml_overlay`) only covers `SelectionConfig` and `CircuitBreakerConfig` — not affected by this change
- `FullConfig.__getattr__` delegates to `.base` — config file only sets `Config` fields, not `FullConfig` sections

## Premises

1. **Remove `PIPELINE_PROJECTS_DIR` env var entirely** — breaking change, documented in CHANGELOG
2. **General global config mechanism** — every `Config` field is settable via `tpo config set <key> <value>`, not just `projects_dir`
3. **XDG-style search path** — `${XDG_CONFIG_DIR:-~/.config}/tpo/config.yaml` → `~/.tpo/config.yaml` → `${HERMES_HOME:-~/.hermes}/tpo.yaml`
4. **Schema validation** — config values validated against `Config` dataclass fields and types at set-time and load-time

## Approaches Considered

### Approach A: Thin YAML overlay — flat dict

Added a `from_config_file()` classmethod that reads a YAML file as a flat dict, coerces values, and layers on `default()`. No schema validation — typos silently stored but not applied.

**Tradeoff**: Smallest diff (~1 classmethod + 1 CLI subparser). Fragile — no validation, no self-documenting file.

### Approach B: Schema-driven config with generated skeleton (CHOSEN)

New module `config_loader.py` with `load_global_config()` that reads YAML, validates keys/types against `Config` dataclass fields. `tpo config init` writes a skeleton with commented defaults and explanatory comments. `tpo config set` validates before writing.

**Tradeoff**: ~2 new files + 1 CLI subparser but schema-validated, self-documenting, and extendable. Catches errors at set-time, not runtime.

### Approach C: Config-as-source with dot-path notation

Full hierarchical YAML mirroring `FullConfig` structure. Dot-path notation for CLI (`tpo config set base.projects_dir /opt`). Covers `SelectionConfig` and `CircuitBreakerConfig` too.

**Tradeoff**: Most future-proof but largest diff. Changes global config loading contract. Over-engineered for current needs.

## Recommended Approach

**Approach B** — schema-driven config with generated skeleton.

**Why B over A**: A flat dict stores bad values silently. Schema validation catches `projects_dir: not/a/path` or `default_timeout: fast` at set-time, not at runtime three weeks later.

**Why B over C**: Dot-path notation and hierarchical YAML solve a problem that doesn't exist yet. Every `Config` field being settable is handled by flat key→field mapping. If nested config is needed later, B's loader extends to it without changing the CLI interface.

```python
from __future__ import annotations

import dataclasses
import os
import yaml
from pathlib import Path

from .config import Config

# XDG-style search paths — first existing file wins
def _search_paths() -> list[Path]:
    xdg = os.environ.get("XDG_CONFIG_DIR", str(Path.home() / ".config"))
    hermes_home = os.environ.get("HERMES_HOME", str(Path.home() / ".hermes"))
    return [
        Path(xdg) / "tpo" / "config.yaml",
        Path.home() / ".tpo" / "config.yaml",
        Path(hermes_home) / "tpo.yaml",
    ]

def find_config_file() -> Path | None:
    """Return path to first existing config file, or None."""
    for p in _search_paths():
        if p.is_file():
            return p
    return None

def default_config_path() -> Path:
    """Return the preferred path for a new config file (first XDG path)."""
    return _search_paths()[0]

def load_global_config() -> Config:
    """Load config from first found YAML file, validated against Config schema.
    
    Returns a Config instance with any fields found in the file applied on top
    of Config.default(). Raises ValueError for unknown keys or type mismatches.
    """
    config_file = find_config_file()
    if config_file is None:
        return Config.default()
    
    raw = yaml.safe_load(config_file.read_text())
    if raw is None or not isinstance(raw, dict):
        return Config.default()
    
    return _coerce_config(raw, config_file)

def _coerce_config(raw: dict, source: Path) -> Config:
    """Validate and coerce a flat dict to a Config instance."""
    fields = {f.name: f for f in dataclasses.fields(Config)}
    overrides = {}
    errors = []
    
    for key, value in raw.items():
        if key == "_comment" or key.startswith("_"):
            continue  # Skip internal/comment keys
        if key not in fields:
            errors.append(f"unknown config key {key!r} in {source} — "
                         f"valid keys: {', '.join(sorted(fields.keys()))}")
            continue
        field_type = fields[key].type
        try:
            overrides[key] = _coerce_value(value, field_type, key, source)
        except (TypeError, ValueError) as e:
            errors.append(f"invalid value for {key!r} in {source}: {e}")
    
    if errors:
        raise ValueError("\n".join(errors))
    
    if not overrides:
        return Config.default()
    
    return dataclasses.replace(Config.default(), **overrides)

def _coerce_value(value, target_type, key: str, source: Path):
    """Coerce a YAML value to the expected Config field type."""
    if target_type is Path:
        return Path(str(value)).expanduser()
    elif target_type is int:
        return int(value)
    elif target_type is float:
        return float(value)
    elif target_type is bool:
        if isinstance(value, bool):
            return value
        if isinstance(value, str):
            if value.lower() in ("true", "1", "yes"):
                return True
            if value.lower() in ("false", "0", "no"):
                return False
            raise ValueError(f"cannot coerce {value!r} to bool")
        return bool(value)
    elif target_type is str:
        # YAML `null` → None; converting None to str gives "None", not "null".
        # Guard: if value is None and the field accepts string literals, reject it.
        if value is None:
            raise ValueError("YAML `null` is not a valid string value — use quoted string (e.g. \"null\")")
        return str(value)
    else:
        # Literal types (KanbanAdapterName = Literal["null", "hermes"]) —
        # Literal is a type hint, not a runtime validator. Explicitly check
        # against known literal values from the Config dataclass defaults.
        valid = _get_literal_values(target_type, key)
        if valid is not None:
            str_val = str(value)
            if str_val not in valid:
                raise ValueError(f"must be one of {valid}, got {str_val!r}")
            return str_val
        return value

_KANBAN_ADAPTER_VALUES = {"null", "hermes"}

def _get_literal_values(target_type, key: str) -> set[str] | None:
    """Return valid literal values for known Literal-typed Config fields."""
    if key == "kanban_adapter":
        return _KANBAN_ADAPTER_VALUES
    return None

def validate_config_key(key: str) -> str:
    """Validate that a key is a valid Config field name. Raises ValueError."""
    fields = {f.name for f in dataclasses.fields(Config)}
    if key not in fields:
        raise ValueError(f"unknown config key {key!r} — valid keys: {', '.join(sorted(fields))}")
    return key

def validate_config_value(value: str, key: str) -> any:
    """Parse and validate a CLI value string against a Config field type."""
    fields = {f.name: f for f in dataclasses.fields(Config)}
    field_type = fields[key].type
    return _coerce_value(value, field_type, key, Path("<cli>"))

# Skeleton constant — used by `tpo config init`
SKELETON = """\
# tpo global configuration — generated by `tpo config init`
# Lines starting with # are comments and ignored by the loader.
# Uncomment and modify any setting to override the default.
#
# Env var overrides (PIPELINE_*) take precedence over this file.
# Reload: changes take effect on the next `tpo` command — no restart needed.

# Directory for pipeline file locks (default: ~/.hermes/pipeline_locks)
# lock_dir: ~/.hermes/pipeline_locks

# Root directory containing all pipeline project subdirectories
# (default: ~/projects)
# projects_dir: ~/projects

# Directory for pipeline state files (default: ~/.hermes)
# state_dir: ~/.hermes

# Claude CLI command to invoke (default: claude)
# claude_cmd: claude

# Subdirectory within each project for checkpoints
# (default: .hermes/pipeline_checkpoints)
# checkpoint_subdir: .hermes/pipeline_checkpoints

# Subdirectory within each project for ready-for-review markers
# (default: .hermes/ready_for_review)
# ready_for_review_subdir: .hermes/ready_for_review

# Subpath within project for the TODO ID counter file
# (default: .hermes/todo_id_counter)
# counter_file_subpath: .hermes/todo_id_counter

# Default timeout in seconds for pipeline phases (default: 1800)
# default_timeout: 1800

# Kanban adapter: "null" (no kanban) or "hermes" (default: null)
# kanban_adapter: "null"

# Maximum number of kanban outbox entries (default: 500)
# kanban_outbox_cap: 500

# Log file subpath within state_dir (default: pipeline.log)
# log_file_subpath: pipeline.log

# Number of days to retain rotated log files (default: 7)
# log_retention_days: 7

# Slack channel for pipeline notifications (default: none)
# slack_channel: ""
```

### File: `hermes_pipeline/config.py` — changes to `Config.from_env()`

The `from_env()` method becomes a three-layer loader: `default()` → `load_global_config()` → env vars.

```python
@classmethod
def from_env(cls) -> Config:
    # Layer 1: defaults
    base = cls.default()
    
    # Layer 2: global config file
    from .config_loader import load_global_config
    base = load_global_config()
    
    # Layer 3: environment variable overrides
    env_map = {
        "PIPELINE_LOCK_DIR": ("lock_dir", Path),
        "PIPELINE_STATE_DIR": ("state_dir", Path),
        "PIPELINE_CLAUDE_CMD": ("claude_cmd", str),
        "PIPELINE_KANBAN_ADAPTER": ("kanban_adapter", str),
        "PIPELINE_SLACK_CHANNEL": ("slack_channel", str),
    }
    # NOTE: PIPELINE_PROJECTS_DIR removed — use config file instead
    
    overrides = {}
    for env_key, (attr, ctor) in env_map.items():
        val = os.environ.get(env_key)
        if val is not None:
            overrides[attr] = ctor(val)
    if not overrides:
        return base
    from dataclasses import replace
    return replace(base, **overrides)
```

Key changes:
- `PIPELINE_PROJECTS_DIR` removed from `env_map` (breaking change)
- `load_global_config()` called between `default()` and env var processing
- All remaining env vars still work as overrides on top of the config file

```python
def _cmd_config_init(args, config):
    from .config_loader import default_config_path, SKELETON
    path = default_config_path()
    if path.is_file() and not args.force:
        print(f"Config file already exists at {path}")
        print(f"Use --force to overwrite.")
        return 1
    path.parent.mkdir(parents=True, exist_ok=True)
    path.write_text(SKELETON)
    print(f"OK: created {path}")
    return 0

def _cmd_config_get(args, config):
    """Show the current effective value of a config key.

    Reads through the full three-layer stack (default → file → env var)
    and prints the final value. The value comes from Config.from_env(),
    which is the user's active config.
    """
    from .config_loader import validate_config_key
    from .config import Config
    key = validate_config_key(args.key)
    cfg = Config.from_env()
    value = getattr(cfg, key)
    print(f"{key}: {value}")
    return 0

def _cmd_config_set(args, config):
    from .config_loader import (validate_config_key, validate_config_value,
                                 find_config_file, default_config_path)
    key = validate_config_key(args.key)

    # Pass the raw CLI string directly to _coerce_value — no double YAML parsing.
    # _coerce_value handles type coercion (int, Path, bool, str, Literal).
    # For Path types, _coerce_value already calls .expanduser() to handle ~.
    coerced = validate_config_value(args.value, key)

    config_file = find_config_file()
    if config_file is None:
        # Auto-create an empty file so `set` works without requiring `init`.
        config_file = default_config_path()
        config_file.parent.mkdir(parents=True, exist_ok=True)
        config_file.write_text("# tpo global configuration\n\n")

    # Use regex-based in-place replacement to preserve comments and structure.
    # This handles both commented-out lines (# key: value) and active lines (key: value).
    import re
    text = config_file.read_text()
    pattern = rf'^(#\s*)?{re.escape(key)}:\s*.*$'
    if re.search(pattern, text, re.MULTILINE):
        # Replace existing line, keeping it active (uncommented)
        replacement = f'{key}: {_format_value(coerced, key)}'
        text = re.sub(pattern, replacement, text, count=1, flags=re.MULTILINE)
    else:
        # Key not in file — append at end
        replacement = f'\n{key}: {_format_value(coerced, key)}\n'
        text = text.rstrip() + replacement
    config_file.write_text(text)
    print(f"OK: set {key} = {coerced}")
    print(f"File: {config_file}")
    return 0

def _format_value(value, key):
    """Format a Python value back to YAML for writing to config file."""
    if isinstance(value, bool):
        return "true" if value else "false"
    elif isinstance(value, str):
        # Quote strings that could be misinterpreted by YAML parser.
        # "null", "true", "false", empty strings, and strings starting with ~
        if value.lower() in ("null", "true", "false", "yes", "no") or value == "" or value.startswith("~"):
            return f'"{value}"'
        return value
    elif isinstance(value, int | float):
        return str(value)
    return str(value)

def _cmd_config_path(args, config):
    from .config_loader import find_config_file, default_config_path
    existing = find_config_file()
    if existing:
        print(f"Using: {existing}")
    else:
        print(f"No config file found.")
        print(f"Default path: {default_config_path()}")
        print(f"Run `tpo config init` to create one.")
    return 0
```

The `config` command should be handled as a bootstrap subcommand (like `skills`) — it doesn't need `Config.from_env()` because it reads/writes the config file directly, not the runtime config.

### Module-level caching

NOT INCLUDED. CLI tools are one-shot invocations — `Config.from_env()` is called once per process.
The only multi-call scenario is the test harness, which can clear a simple mtime-based cache
between `set` and `get` calls. Removing caching eliminates the stale-cache-after-`set` bug entirely.

## Open Questions

1. **Auto-create vs require init?** RESOLVED: `_cmd_config_set` now auto-creates an empty config file if none exists (convenience wins; users who want comments can run `init`). `tpo config init` still useful for generating the full documented skeleton.
