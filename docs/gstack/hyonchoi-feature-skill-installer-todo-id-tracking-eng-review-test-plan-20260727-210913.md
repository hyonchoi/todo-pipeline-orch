## Affected Pages/Routes
- CLI/skill workflow: todos-manager `--audit`, `--convert`, `--add`, `--archive`, `--list`, `--revise` — verify sectioned TODOS.md grammar.
- CLI: `tpo recover-counter <project>` — verify compatibility counter recovery only trusts `NEXT_TODO_ID` under `## Metadata`.

## Key Interactions to Verify
- Run audit on a legacy unsectioned TODOS.md and confirm it migrates to `## Metadata`, `## Entry Schema`, `## Entries`.
- Add a TODO after migration and confirm the new entry lands under `## Entries` and increments metadata atomically.
- Archive completed entries and confirm TODO-like examples under `## Entry Schema` are not moved.
- List/revise active entries and confirm only entries under `## Entries` are visible/editable.

## Edge Cases
- `NEXT_TODO_ID` under `## Entry Schema` or `## Entries` is rejected and repaired.
- Duplicate metadata across sections is rejected and repaired.
- TODO-like schema examples are ignored by parse, audit, dependency validation, archive, list, and revise paths.
- CRLF sectioned files preserve valid parsing and repair behavior.

## Critical Paths
- Full migration path: legacy file -> audit repair -> second audit idempotent -> add -> recover-counter.
- Consumer regression path: schema example containing `TODO-99` and `[x]` status must not affect active entry count, dependencies, archive, list, or revise.
