# native-sdd is the default phase profile

`native-sdd` is the default phase profile for new contracts written by `tpo init`, and `gstack` is deprecated. `gstack` remains bundled and fully supported until a later major release removes it.

**Context.** The Spec that introduced pluggable profiles (`SPEC.md`, "Boundaries") kept `gstack` as the default so that existing projects needed no migration. Since then the product direction has changed: native-sdd is the intended default and the gstack flow is obsolete. native-sdd is the profile whose phases are driven by the pipeline itself rather than by external skills: it requires a Plan (`requires_plan`), compiles the Plan's `json tpo-plan` manifest into ordered worker/controller-gate pairs (ADR-0001), and reconciles review and finish from Kanban results, stopping at a human gate (ADR-0002), instead of delegating them to gstack `/review` and `/ship` phases. Keeping gstack as the implicit default would steer every new project onto the flow we intend to retire.

**Decision.** `tpo init` writes `profile: native-sdd` unless `--profile` says otherwise. `profiles/gstack/phases.yaml` carries `deprecated: true`; `tpo init --profile gstack`, `tpo doctor`, and `tpo tick` emit a deprecation notice for a gstack contract. A contract with no `profile` key keeps resolving to `gstack` (the legacy implicit default), so existing projects continue to run unchanged; `tpo doctor` reports it on a `DEPRECATED:` line and `tpo tick` warns once per tick. Migration is explicit: `tpo init <project> --force --profile native-sdd` rewrites the contract; it is never performed automatically.

**Consequences.** Existing `.hermes/` state and in-flight ticks are unaffected because the implicit-gstack resolution is unchanged; the SPEC "Always" boundary on the default is superseded by this ADR, while its "Ask first" and "Never" boundaries on phase_key stability and fail-closed profile changes still hold. The `tpo test` live harness gains a bounded multi-tick driver so a native-sdd run advances through review and finish to the PR handoff, where the human gate blocks it; a single tick cannot exercise native-sdd end to end. Non-goals: the GitHub issue-form Phase dropdown stays gstack-shaped, and gstack is not removed or renamed here.

**Alternatives considered.** A hard cutover (remove gstack, fail closed on gstack contracts) was rejected: it would strand in-flight ticks and force a migration during an unrelated upgrade. Flipping the implicit default (contracts without `profile` resolving to native-sdd) was rejected: it silently changes the phases a running project executes, which the SPEC "Never" boundary forbids; the default flips only for contracts `tpo init` writes, and every existing contract keeps behaving as before until its owner migrates.
