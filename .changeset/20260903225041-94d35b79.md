Plan-manifest compilation no longer emits a per-task `validate:<task-id>` controller gate: each Plan task is one worker card chained onto the previous worker, so a manifest run never opens a human-input boundary between tasks. Validation is unchanged in strength — TPO still parses and verifies every worker's `metadata.tpo_result` and Git facts before the chain advances, now deriving "already validated" from board state (a task a later card is built on is verified by immutable topology; the chain tip is additionally verified against current HEAD and a clean worktree), and every task's reported commit must be an ancestor of the run branch's HEAD (`unreachable_commit`), which the per-task gate never checked. A validation failure reports no tick progress and logs a bounded diagnostic instead of blocking a card. Independent review now opens on the last Plan worker. A failure also writes a run-scoped `result-validation-blocked` marker beside the run's other evidence; it blocks nothing and is cleared when the results validate. Runs registered before this change keep their `validate:<id>` step keys and their gates are still completed, so they can be resumed. Downgrading is not: a run registered after this change lists no `validate:<id>` keys, which an older TPO rejects as `registration_invalid` forever, so do not downgrade past this release while a manifest run is active. `pinned_tick_budget` is now one tick per Plan task instead of one per worker/gate pair.
